## Design

**ADR 0006: `type_info` contract v2**, replacing the unused v1 header role (`il2cpp.h` already comes from il2cpp_dump):

```python
class TypeInfo(Protocol):
    def types(self, binary: Path, metadata: Path, dump_dir: Path, unity_version: str,
              classes: Path, out: Path) -> dict: ...
CONTRACT = ArtifactContract("type_info", files=("nodes.json",))
```
- `classes`: JSON `[{"assembly": "UnityEngine.UI", "class": "UnityEngine.UI.Image"}, …]`, written by the stage from MonoScripts.
- `nodes.json`: `{"unity_version", "classes": {"<asm>|<fullname>": [{"m_Type","m_Name","m_Level","m_MetaFlag"}…]},
  "missing": {"<asm>|<fullname>": "<error>"}}`, sorted. Adapters use only the inputs they need.
- Output goes to `types/<v>/`. The ADR also records that the assets stage uses UnityPy (MIT) in-process as its asset
  reader, the same way formats parse bytes. The type-tree tool stays behind the port.

**Adapters** (TypeTreeGeneratorAPI is imported lazily; generator factory injectable for tests):
- `src/zk/adapters/typetree_dummydll.py`: `TypeTreeGenerator(unity_version)`. Loads every `dump_dir/DummyDll/*.dll` in
  sorted order (il2cpp_dump contract verified first), then writes `get_nodes` for each requested class. Each error goes to `missing`.
- `src/zk/adapters/typetree_cpp2il.py`: checks `hasattr(DLL, "TypeTreeGenerator_loadIL2CPP")` and gives a clear
  RuntimeError if it is absent. Then runs `load_il2cpp(binary bytes, metadata bytes)` and the same node dump. It goes into `zk.toml` **only** if
  step 9 shows it loads metadata v39. Either way, docs/ports/type_info.md records the observed result.
- `zk.toml`: `type_info = "typetree_dummydll"`.

**Stage package `src/zk/stages/assets/`** (`NAME="assets"`, args `--abi`, `--force`, `--only TYPE…`, `--limit`):
- `__init__.py`: `execute`. Needs `unpack` and `code` records for this version and ABI. Unity version =
  `ctx.ws.fact("unity_version")`, never a constant. Data dir = `unpacked/<v>/<stem>/assets/bin/Data`, from the unpack record's metadata path.
- `_unity.py`: the only UnityPy importer (lazy import, clear error if not installed). `load(data_dir)` returns plain
  `AssetObject` records (file, path_id, type, name, `read()`, `raw()`, `read_nodes(nodes)`) so the rest can be tested with fakes.
- `_export.py`: helpers adapted from SSA (`export_source`, `_export_typetree` with raw-bytes fallback, the resumable index).
  PkgBase/UnityCache source logic is dropped. Per type: Texture2D/Sprite → PNG; AudioClip → `samples` as WAV (FMOD in UnityPy);
  Font → `m_FontData` as .ttf/.otf by magic; TextAsset → bytes; Shader → listed in `shaders.json` (name, file, path_id).
  MonoBehaviour → JSON through port nodes. On failure: `raw/<file>_<path_id>.bin` plus a failure entry
  `{script_class, assembly, error, reason}`. `reason` is one of `no_script`, `class_missing_in_type_info`
  (TTG `missing`), `read_error`, or `unexplained`.
- `_scene.py`: maps Main.unity to `levelN` through BuildSettings scenes. Dumps GameObjects (name, active, layer),
  components (type, path_id), the Transform parent/child tree, and MonoBehaviour `m_Script` → `assembly/fullname`
  into `scenes/Main.json`.
- `_compare.py`: shared with `code` (move `code.compare` there; `code.py` imports it). For each non-game assembly used by a
  MonoBehaviour, it compares `il2cpp/<v>/summary.json` with `il2cpp/<v>/crosscheck/summary.json`. Each differing class is
  tagged `used` or `unused` (not in the MonoBehaviour class set), and assembly-level type gaps get the same tags. `unexplained` =
  differences in used classes with no parser rule. If crosscheck/summary.json is missing, the stage fails with
  "run `zk code` without --skip-crosscheck".
- Index `assets/<v>/index.json`: `{"<file>:<path_id>": {type, out, status}}`, written atomically (tmp + `replace`) every N
  objects and at the end. On a rerun, entries marked done whose output file exists are skipped. `--force` deletes only `assets/<v>/` and `types/<v>/`
  (derived data). `raw/` and `unpacked/` are never written.
- `report.json` + record: inventory counts (counted live from the files, not constants) vs exported counts per type,
  `misses` naming each missed object (file, path_id, name, error), MonoBehaviour `{total, json, failed, by_reason}`,
  `crosscheck` per used assembly, scene summary, and type_info adapter info. The stage raises (nothing recorded) when
  `unexplained` failures or crosscheck differences remain.

Output layout: `assets/<v>/{textures,sprites,audio,fonts,text,monobehaviours/<Asm>/<Class>/,raw,scenes}/`, plus
`shaders.json`, `index.json`, `report.json`.

**Deps** (`pyproject.toml`): add extra `assets = ["UnityPy==1.25.4", "TypeTreeGeneratorAPI==0.0.10"]` and add both to `dev`
so CI type-checks/imports them. Tests never initialise the native DLL or load real files.

## Tests (offline, synthetic)
- `tests/test_type_info_adapters.py`: both adapters run with a fake generator class, checking DLL load order, nodes.json shape,
  that `missing` is filled on errors, that the unity_version passed through is the one given, the cpp2il RuntimeError when the IL2CPP export is absent, and the contract.
- `tests/test_assets_export.py`: fake `AssetObject`s cover the PNG/WAV/font/text writers, the raw fallback with the
  failure-reason mapping, index resume (a second run skips; deleting an output redoes it), and the atomic index write.
- `tests/test_assets_scene.py`: a synthetic GameObject/Transform/MonoBehaviour graph → hierarchy JSON.
- `tests/test_assets_compare.py`: used/unused tagging, assembly type gaps, `unexplained`. Existing `test_stage_code` still passes.
- `tests/test_stage_assets.py` + `tests/fakes/fake_type_info.py`: run via `cli.main` after acquire/unpack/code fakes, with
  `_unity.load` monkeypatched. Checks that the unity_version comes from the manifest (a different synthetic fact flows through),
  the report counts and misses, and that a missing crosscheck or an unexplained failure gives exit 2 with nothing recorded.
- Any csharp_dump naming/counting fix found in step 10 gets a synthetic test in `tests/test_csharp_dump.py`.

## Risks
- The DummyDll stubs have field metadata, but TTG's AssetsTools backend may need `[SerializeField]`/attribute info that
  Il2CppDumper keeps. If many classes fail, try the `AssetRipper` or `AssetStudio` TTG backend before reporting blocked.
- MonoScripts point to assemblies with no DLL (e.g. Timeline/TMP names in Unity 6). The stage resolves them through the
  il2cpp summary's class→assembly map, and a class that really is missing gets `class_missing_in_type_info`. It is listed, not hidden.
- ASTC/ETC texture decoding and FMOD audio depend on UnityPy's native wheels. A failed decode is a named miss in the report.
- The doneWhen text says `docs/ports/type-info.md`, but every port page uses the module name (`type_info.md`). I'll keep
  `type_info.md` and point this out when reporting Done.
- `zk code` with crosscheck reruns the dump and may fail the game-assembly type check. `crosscheck.json` is still written,
  so assets can read `crosscheck/summary.json`. Any game-assembly mismatch is a code-stage issue I'll report, not hide.
- Il2CppInspector or Cpp2IL may not support v39. The Cpp2IL adapter then stays disabled, as the criterion allows.
